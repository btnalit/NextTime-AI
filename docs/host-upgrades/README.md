# 主机升级报告

每次主机升级一份报告，文件名 `<日期>-<起点版本>-to-<目标版本>.md`。报告由维护者本地的执行会话写，走 PR 入库，
分阶段追加提交，全部阶段做完再合（维护者 2026-11-27 定）。合并线程按公开仓库规则审过后合入，
并在随后的记录里更新 `docs/STATUS.md` 的主机行与 `docs/state/loop.json` 的 `host`。

## 写什么、不写什么

- **照实写**：版本与提交、迁移数、各步命令与结论、验收计数、日志文件名、决定和它们的理由。
- **写成占位符**：主机别名写 `<主机>`，检出目录写 `<检出目录>`，数据目录写 `${NEXTTIME_DATA}`，内网地址和网段不写。
- **写角色名**：账号与工作区写 admin、服务账号「测试」、夹具账号、`stability` 工作区这类角色名，不写 id 或 id 前缀
  （协调线程 2026-11-27 定）。需要 id 时记在 gitignored 的 `docs/private/`。
- **只记在 `docs/private/`**：密钥、token、Handle、key 的值或片段，模型供应商与模型名，花费。
- 提交前把报告、提交说明和 PR 正文都扫一遍：没有上面这些，也没有私网 IPv4 字面量（CI `guards` 会拒）。
